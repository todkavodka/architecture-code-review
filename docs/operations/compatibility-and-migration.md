# Совместимость и миграция

`Review Suite` рассчитан на повторное использование сохранённых пакетов аудита
между сеансами и ревизиями Skill. Старый пакет нужно понять и при необходимости
согласовать, но не следует автоматически считать его повреждённым.

## Основной принцип

```text
старый пакет != повреждённый пакет
отсутствие современных метаданных != принятое современное состояние
```

Старый пакет может быть пригоден для чтения, `USE_EXISTING` или ограниченного
согласования. Однако отсутствие новых полей не доказывает актуальность или
прохождение современных проверок.

## Признаки старого пакета

- отсутствует STM в современной форме;
- старый `INDEX.md` не содержит полей координатора;
- Test Review сохранён только старым endpoint;
- итоговый Markdown не имеет метаданных жизненного цикла `PRJ-*`;
- отсутствует запись зависимостей или отпечаток проекции.

Это признаки более ранней модели, а не автоматический вердикт об ошибке.

## Консервативное согласование

| Сценарий | Что делает процесс |
|---|---|
| `USE_EXISTING` | Использует принятый пакет, если запрошенный документ и его источники истины пригодны; не мигрирует всё без необходимости. |
| `RESUME` | Восстанавливает первую незавершённую зависимость и согласует только нужное состояние. |
| `EXTEND` | Добавляет только зависимую область, нужную новому модулю или документу. |
| `REVALIDATE` | Использует старые материалы как исторический контекст, но затронутый технический смысл проверяет по текущим правилам. |

## Старый Test Review

Значения

```text
REVIEW_ONLY
REVIEW_PLUS_TEST_PLAN
```

являются входом совместимости, а не современными пунктами меню. Согласование
консервативно:

```text
REVIEW_ONLY
  -> Test Assurance = true
  -> все необязательные документы = false

REVIEW_PLUS_TEST_PLAN
  -> Test Assurance = true
  -> Test Plan = true
  -> все остальные необязательные документы = false
```

Согласование не добавляет документы, которых старое состояние не доказывает.

## Старые As-Built, STM и проекции

Старый As-Built нельзя автоматически считать принятой STM. Его фактическое
содержание может служить историческим контекстом или кандидатом, но современная
модель требует проверки базовой ревизии и доказательств через Technical Model
Gate.

Markdown без метаданных `PRJ-*` не становится `CURRENT` автоматически. Для
регистрации нужно определить владельца, назначить идентификатор проекции,
разрешить зависимости, проверить документ относительно принятого смысла и
зафиксировать отпечаток и ревизию. Если источник смысла не удаётся установить,
регистрация останавливается и работа возвращается во владеющий технический
процесс.

## Добавление полей координатора

Недостающие поля старого `INDEX.md` добавляются только при необходимости. При
этом нельзя превращать компактное состояние в источник истины, маскировать
неизвестное состояние как `VALID` или переписывать историю пакета.

## Ограниченная политика совместимости

Документация может честно обещать следующее:

1. старый пакет не уничтожается молча;
2. отсутствие современных метаданных обнаруживается явно;
3. согласование выполняется только в области текущей задачи;
4. старый принятый смысл не усиливается до современной технической истины без
   актуальных доказательств;
5. современные утверждения об итоговых документах и актуальности требуют
   современных проверок.

Проект не публикует гарантии совместимости по семантическим версиям схемы. Если
миграция неоднозначна или не поддерживается текущими контрактами, процесс
останавливается для ручного согласования; он не угадывает преобразование.
Организации, которым нужна строгая долгосрочная матрица, фиксируют SHA Skill
рядом с правилами управления пакетами и проверяют обновления на
представительных пакетах до массового развёртывания.

## Обновление во время незавершённой работы

Не запускайте `NEW` только из-за обновления Skill. Используйте `RESUME`;
координатор сверит сохранённое состояние и ревизии владеющих артефактов,
добавит необходимые поля в ограниченной области либо остановится при
неоднозначной семантической несовместимости.

## Когда нужно остановиться

Не продолжайте техническую работу, если неясен владелец старого артефакта,
потеряна привязка к базовой ревизии, технический смысл нельзя отделить от
представления, невозможно восстановить зависимость или компактная запись
конфликтует с владеющим артефактом. Сохраните материал как исторический
контекст и вернитесь к адресной технической повторной проверке.
