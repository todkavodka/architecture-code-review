# Установка

## Поддерживаемая модель установки

`architecture-code-review` — файловый инструмент. Агент обнаруживает его в
каталоге навыков и использует `SKILL.md` как точку входа.

Ожидаемый корень обнаружения для среды, поддерживающей это соглашение:

```text
~/.agents/skills/architecture-code-review
```

## Требования к среде запуска

Чтобы инструмент мог выполнять сохраняемые процессы, среда запуска должна уметь:

- обнаруживать файловый инструмент и читать его точку входа `SKILL.md` вместе со
  ссылочными файлами;
- читать анализируемый репозиторий и выполнять Git-операции, нужные для выбора
  базовой ревизии;
- сохранять Markdown-артефакты в анализируемом репозитории, если выбран
  возобновляемый пакет аудита;
- сохранять точные идентификаторы и токены без локального переименования;
- восстанавливать работу из состояния файлов после нового сеанса агента.

Также нужны Git и права доступа к анализируемому репозиторию. Сам инструмент не
требует отдельной базы данных или фонового сервиса.

## Статус сред запуска

Документация показывает установку в каталоге `~/.agents/skills`, потому что его
используют файловые среды с поддержкой навыков. Codex и OpenCode приведены как
примеры таких сред, а не как обещание сертифицированной поддержки каждой версии.

Проект не ведёт формальную матрицу протестированных версий сред запуска. Среда, которая
выполняет требования выше, совместима по модели установки; среда без проверки
в конкретной организации считается непроверенной. До массового внедрения
проверьте обнаружение `SKILL.md`, доступ к Git и создание небольшого пакета
аудита на представительном репозитории.

## Установка последней версии `main`

```bash
git clone \
  https://github.com/todkavodka/architecture-code-review.git \
  ~/.agents/skills/architecture-code-review
```

После установки начните новый сеанс агента, чтобы он заново обнаружил каталог
навыков.

## Проверка установки

```bash
cd ~/.agents/skills/architecture-code-review
git status --short
git branch --show-current
git rev-parse HEAD
```

Ожидается:

- каталог существует;
- текущая ветка обычно `main`;
- `git status --short` пуст, если вы не вносили локальных изменений;
- `git rev-parse HEAD` возвращает установленную ревизию.

После этого попросите агента использовать `architecture-code-review`. Если
инструмент не обнаруживается, см. [Диагностика проблем](../operations/troubleshooting.md).

## Установка фиксированной ревизии

Для воспроизводимой среды лучше закрепить конкретный коммит:

```bash
git clone \
  https://github.com/todkavodka/architecture-code-review.git \
  ~/.agents/skills/architecture-code-review

cd ~/.agents/skills/architecture-code-review
git checkout <commit-sha>
```

Такое переключение переводит репозиторий в состояние отсоединённого `HEAD`. Это
допустимо для закреплённой установки, но обновлять её нужно осознанно.

## Обновление

Для обычной установки на `main`:

```bash
cd ~/.agents/skills/architecture-code-review
git switch main
git fetch origin --prune
git pull --ff-only
```

`--ff-only` защищает от случайного слияния локальных изменений с историей
удалённого репозитория.

После обновления начните новый сеанс агента.

## Локальные изменения

Не рекомендуется изменять установленный инструмент напрямую. Локальные
изменения усложняют:

- воспроизводимость;
- сравнение пакетов аудита между командами;
- обновление;
- диагностику расхождений между документацией и нормативными контрактами.

Если локальная адаптация необходима, храните её в отдельной ветке или форке и
фиксируйте точную ревизию в инженерной документации команды.

## Удаление

Если в каталоге нет нужных локальных изменений:

```bash
rm -rf ~/.agents/skills/architecture-code-review
```

Удаление инструмента не удаляет пакеты аудита, уже созданные внутри
анализируемых репозиториев.
